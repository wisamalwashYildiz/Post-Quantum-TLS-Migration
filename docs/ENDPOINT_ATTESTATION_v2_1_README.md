# v2.1 — role-separated signed TLS exporter claims (research pilot)

Adds `src/endpoint_attestation_v21.py`, ten tests and an example JSON. Does not modify earlier experiments. Requires existing `src/exporter_binding_v20.py`, `src/live_path.py`, installed `pyOpenSSL` and `cryptography`, OpenSSL CLI. Certificates are self-signed for this localhost experiment.

## What the experiment actually demonstrates

A real Python pyOpenSSL TLS 1.3 connection exports per-session keying material with explicit transaction-nonce context; the initiator and responder create **different role-domain-separated exporter HMAC tags**. Each role signs its own statement using distinct Ed25519 keypairs generated by the test. The public-only verifier checks schemas, nonces, transaction digests, role uniqueness, signatures, and required receipt presence. No Ed25519 secret keys or raw exporter secrets are archived. The roles are two identities in **one Python process with a server thread**, NOT independently isolated security domains.

In the local execution: genuine=ATTESTED; copied_initiator=INVALID; missing_responder=UNRESOLVED; tampered_tag=INVALID; changed_transaction=INVALID; replay=INVALID; wrong_signer=INVALID. **Key negative control**: two artificially fabricated distinct exporter tags, both correctly re-signed by their authorized signers, still produce `ATTESTED`. This is expected and falsifies any claim that signatures alone validate the underlying TLS handshake. The offline verifier has no TLS session secrets and **does not verify either exporter tag mathematically or prove that they came from the same session**. `ATTESTED` means endpoint claims pass signature policy only, not independently verified channel binding.

## How to run — from a NEW Windows PowerShell terminal

```powershell
wsl -d Ubuntu-22.04
```

Then Ubuntu:

```bash
cd "/mnt/d/Articles/Post-Quantum TLS Migration/Post-Quantum TLS Migration-Project"
source "$HOME/pqc-research-venv/bin/activate"
OPENSSL_HOME="$HOME/opt/openssl-3.5.9"
export LD_LIBRARY_PATH="$OPENSSL_HOME/lib64${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
python -m unittest discover -s tests -p 'test_*.py' -v
python src/endpoint_attestation_v21.py --openssl "$OPENSSL_HOME/bin/openssl" --output results/endpoint_attestation_v21
```

Results JSON contains only transaction, signed claims, public keys, and verdicts. Do NOT infer negotiated hybrid group from this run: it does not measure KEX selection. Python `ssl.OPENSSL_VERSION` and pyOpenSSL's linked OpenSSL must be verified independently if claiming a version. This is a single hop, not multi-hop.

## Publication interpretation and decisive direction

The result provides **two controlled counterexamples**: symmetric shared exporter proof can be cloned (v2.0); distinct authenticated roles prevent naïve cloning but cannot establish truthful TLS exporter values (v2.1). A candidate future design must use an independently protected TLS endpoint, bind transaction digest to actual stream ingress/egress, and verify negotiated group on that same connection. Authentication, authorization, anti-replay state persistence, security boundaries, and compromise assumptions must be explicit. Existing RFC channel binding and signed telemetry are prior art; don't claim invention of either.
